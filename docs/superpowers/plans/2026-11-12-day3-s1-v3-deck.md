# Day 3 · S1 deck v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `decks/day3-s1-v3.html` (33 slides) from v2. It fixes every P0 in the review, redesigns slides 5/7/9, uses the brief's five workflow names, and reorders the places where the order hurts understanding.

**Architecture:**
- Content is written first, as outline plus copy docs (the source of truth for titles, visible text, build steps and notes).
- The deck is then edited block by block from a reordered copy of the v2 HTML.
- Speaker notes are injected from the copy doc by a script, so slides and notes can't drift apart.
- Two check tools gate every task:
  - a static lint (Python, stdlib) for titles, prompts, banned phrases, notes, workflow names and timing;
  - a renderer (Node + playwright-core + Edge) for overflow, type size, word budget, visible step changes and back navigation.

**Tech Stack:** single-file HTML/CSS/JS deck (v2 runtime) · Python 3.12 + pytest · Node + `playwright-core` driving `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`.

**Spec:** `docs/superpowers/specs/2026-11-12-day3-s1-v3-deck-design.md` (read it in full before any task). Background: `.review/day3-s1-v2-review-report.md` (finding IDs M*, H*, S*, R*, A*), `AGENTS.md` (deck rules).

## Global Constraints

- The output is one self-contained file, `decks/day3-s1-v3.html`. `decks/day3-s1-v2.html` is never modified.
- 33 slides, `data-n="1"` … `data-n="33"` in deck order. Titles and the sequence come from spec §5, verbatim.
- Look: Swiss Modern, `#ff3300` red, Archivo / Nunito / JetBrains Mono, 1920×1080 stage, v2 runtime (`[data-step]`, `.choices` reveal, `#notes-data` JSON keyed by `data-n`).
- Colour key for slides 5–11: red = the model; black = opencode and its rules; grey/white = tools and data (spec §6.1).
- Workflow names, exactly: `Interview`, `Plan`, `Execute`, `Test / Debug`, `Iterate`. `Approve / Edit / Reject` is a chip under Plan.
- Vocabulary (spec §7 V1): "the model"; "opencode" (first mention "opencode, our coding agent"); "chat products"; "your financial app". Never use "app" for opencode. `financial-app` is the literal folder/repo name.
- The tested prompts stay byte-identical: `prompts/s1.md` lines 22, 67, 97, 119, 147.
- Word budget (from `AGENTS.md`): ≤ 40 visible non-title words per reveal step on teaching slides, ≤ 60 on run and check slides. Prompts inside `.prompt pre` and quiz choices don't count. Never shrink type to fit.
- Minimum type 28 px. Exceptions are only the existing v2 components `.prompt` (26 px), `.chip` (26 px), `.pg` and `.steps-ind`, which are unchanged from v2.
- Continuous loops are allowed only on slide 9 (agent-loop dot), slide 32 (drifting shapes) and `.caret`. Every other animation runs at most 3 times. Every animated class is covered by `prefers-reduced-motion`.
- Placeholders `[FAST MODEL]` / `[SMART MODEL]` stay *(user)*. No provider name is added for the chatbot's AI service; the term is "AI service".
- Timing: the minutes in the copy doc sum to 180, and run-slide minutes sum to ≥ 90 (spec §5 gives 91).

## Review Focus

1. **Back navigation through replace-style frames** (slide 10 frames replace each other; slide 7 shrinks a block). Pressing ← must restore exactly the previous step's state → `render.mjs` back-nav check, owned by Task 1, exercised from Task 5 on.
2. **The presenter notes window (S key) and the bottom notes bar after renumbering.** Every `data-n` must have a note, and no note may sit under an old v2 id → lint `notes` check (Task 1) plus `inject_notes.py` (Task 4).
3. **Copy buttons copy exactly what `prompts/s1.md` says** (HTML entities like `&quot;` and `&#x27;` must decode to the same text) → lint `prompts` check compares decoded `pre` text (Task 1).
4. **The 1280×720 projector size**, where the stage scales down → `render.mjs` runs both sizes (Task 1).
5. **Reduced motion:** a participant with OS reduced-motion on must still see the final state of each step → `render.mjs --reduced-motion` pass (Task 1), run in Task 9.

**Interfaces:**
- Produces, in `check_deck.py`:
  - `Slide` dataclass: `n: str`, `title: str`, `visible: str` (text outside `h1/h2`, `.prompt pre`, `.choices`, `script`), `pres: list[str]` (decoded `.prompt pre` text), `wf: list[str]` (text of every `.wf` element), `notes: str`, `words_max: int | None` (from `data-words-max`).
  - `load_slides(html: str) -> list[Slide]`, built on `html.parser`.
  - `parse_outline(md: str) -> dict[str, str]`: data-n → headline, from numbered rows `| <n> | <headline> | …` of the §5-style table.
  - `parse_copy(md: str) -> dict[str, dict]`: id → `{title, type, minutes:int, notes, exception}`, from the `## <id>. <title>` sections.
  - `parse_prompts(md: str) -> list[str]`: every ```` ```text ```` block, stripped.
  - Checks, each `(slides, …) -> list[str]`: `check_sequence` (data-n 1…N, in order), `check_titles(slides, outline)`, `check_notes(slides)` (non-empty for every n), `check_prompts(slides, prompts)` (every `pre` ∈ prompts, and the 5 tested prompts each appear in some `pre`), `check_banned(slides)`, `check_workflow(slides)`, `check_timing(copy)` (sum = 180, `type: run` ≥ 90), `check_exceptions(slides, copy)`.

- `render.mjs` checks, per slide, per step, at 1920×1080 and 1280×720:

  - (d) the PNG for step k differs from step k−1;
  - (e) after reaching step k, `__deck.prev()` leaves the same set of `.in` elements as step k−1.
