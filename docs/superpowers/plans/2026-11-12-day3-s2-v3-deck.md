# Day 3 · S2 deck v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `decks/day3-s2-v3.html` (27 slides). It resolves every P0/P1 finding of the S2 review, with honest-limits wording, prompts that ask for everything the runs check, the S1 v3 safety routine, and two worked examples.

**Architecture:**
- Content first: outline and copy docs are the source of truth for titles, visible text, build steps and notes. Then the deck is edited section by section from a reordered copy of `decks/day3-s2.html`.
- Notes are injected from the copy doc with the existing `tools/deck-check/inject_notes.py`.
- The existing S1 check tools gate every task: `check_deck.py` (static lint) and `render.mjs` (Edge renderer). They gain an S2 profile and two runtime checks, and S1 results stay unchanged.

**Tech Stack:** single-file HTML/CSS/JS deck (S2 v2 runtime) · Python 3.12 + pytest · Node + `playwright-core` driving `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`.

**Spec:** `docs/superpowers/specs/2026-11-12-day3-s2-v3-deck-design.md` (read it in full before any task, including `## Review Decisions`). Background: `docs/reviews/2026-11-12-day3-s2-review.md` (finding IDs), `AGENTS.md` (deck rules), `decks/day3-s1-v3.html` (style, permission line, two-step push, `.wf` chips).

**Branch:** create `s2-v3` from the current `s1-v3` HEAD; the deck-check tools only exist there. Do not touch `decks/day3-s2.html`, `decks/day3-s1-v3.html` or `decks/day3-s3.html`.

## Global Constraints

- Output: one self-contained file `decks/day3-s2-v3.html`; 27 sections, `data-n="1"`…`"27"` in deck order; titles verbatim from spec §6.
- Look and runtime as S2 v2 / S1 v3: Archivo / Nunito / JetBrains Mono, 1920×1080 stage, `[data-step]` reveals, `.choices` quiz reveal, `#notes-data` JSON keyed by `data-n`, `window.__deck`.
- Workflow chips (`.wf`) use only `Interview`, `Plan`, `Execute`, `Test / Debug`, `Iterate`; `Approve / Edit / Reject` is a chip under Plan (spec §5.1).
- Every prompt `pre` text equals a ```` ```text ```` block in `prompts/s2.md` (decoded). The only `pre` that may contain `[`…`]` is P-FIX (starts `[What I did]`). No `<`…`>` placeholders in any `pre`.
- Run slides: one open prompt box at a time; each click reveals the next box and collapses the previous one to a `✓ <step name>` chip (spec §8, Review Decisions).
- Recovery: no copyable recovery prompt. "Stuck?" lines read `Stuck? Raise your hand — we move you to checkpoint <name>.`
- Permission line on slides 12, 13, 22 (verbatim, spec §5.3). Push = P-PUSH1 then P-PUSH2(fixed message) on slides 12, 14, 23.
- Prototype chip `Training prototype — not investment advice.` on slides 17 and 23.
- Word budget: ≤ 40 visible non-title words per step on teaching slides, ≤ 60 on run/check slides; all `.prompt pre` text and quiz choices are excluded; any `data-words-max` needs a matching `exception:` in the copy doc. Never shrink type.
- Minimum type 28 px everywhere, including `.prompt pre` (remove v2 `.prompt.sm` 26 px usage).
- Motion: `packet`, `pulse`, `flow`, `float` run 3 iterations then settle; only the slide 26 drifting shapes and `.caret` loop forever; every animated class has a `prefers-reduced-motion` rule.
- Timing: copy-doc minutes sum to 180; run minutes = 110.
- All S2 prompts are UNTESTED; each run slide's notes start with `[UNTESTED]`.

## Review Focus

1. **Back navigation through collapsing prompt boxes.** ← after a reveal must re-open the previous box and remove its ✓ chip → `render.mjs` (e) prev-restores, exercised on slides 11–14, 21–23 in Tasks 6–7.
2. **Hidden Copy buttons and Space.** Tab must not reach a button in an unrevealed step, and Space on a focused Copy button must not advance the deck → new `render.mjs` check (f), Task 1, fixed in Task 4.
3. **Long prompts at 1280×720 with 28 px type** (Run 2a spec prompt ≈ 120 words) → `render.mjs` (a) bounds at both sizes, Task 6.
4. **Copy text vs. prompts file with entities** (`&quot;`, `→`, `—`) → `check_prompts` compares decoded text, profile s2, Task 1; run in Tasks 6–7.
5. **Reduced motion:** transfer dots and delayed cards must show their final state → `render.mjs --reduced-motion` in Task 9; rules added in Task 4.
