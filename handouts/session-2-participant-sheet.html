The refused-request test

Ask the agent exactly:

“Using budi’s signed-in practice session, send a direct read request to /api/admin/users, not through the menu. Show only the response status, never the sign-in credentials. Do not change any data.”

Expected: 403 Refused. This means a signed-in User was refused. A missing sign-in gives 401 instead and does not prove the User check. Ask the facilitator if the app uses a different route. Prompt 6 also checks refusal when reading the audit trail.
